## 它真的在做什么

三个模块串成一条线：**倾诉 → 记录 → 预警**，对应开题汇报第 5 页。

| 模块 | 页面对应 | 实际实现 |
|---|---|---|
| 匿名树洞 | 第 5 页入口 | 脱敏 → 情绪识别 → 风险分级 → RAG 话术，全链路真实运行 |
| 情绪档案 | 第 5 页"觉察" | SQLite 存储每次情绪分值，生成 30 天曲线、情绪构成、每周小结 |
| 暖光预警 | 第 5 页"兜底" | L1 轻触 / L2 暖光弹层 / L3 危机协议，只推给用户本人 |

### 三条流水线原则（第 6 页）在代码里的落点

1. **先脱敏，再进模型** — `engine.sanitize()` 在入口剥离姓名、手机号、学号、身份证、宿舍号、院系/导师称谓，替换为占位符后**才**进入分析。
2. **回复不许自由发挥** — `knowledge.py` 是 12 张知识卡构成的语料，`retrieve()` 检索相似度不足时**直接说"我不确定"**（返回 `FALLBACK`），绝不硬套不相关的卡片；越界提问（诊断/用药）走 `OUT_OF_SCOPE` 固定边界话术。
3. **预警宁可信其有** — `engine.assess_risk()` 只要命中高危词就无条件判 L3，不受情绪分值影响；输出前还有一道 `_safe()` 检查禁用表述（"你患有…""吃药""一定会好"等）。

> 界面上每条 AI 回复都带"依据 N 条"，点开可以看它引用了哪张知识卡 —— 这是"不许自由发挥"的可视化证明。

## 界面导览

- **树洞页**：首次进入有知情同意；底部有情绪快捷语；发送前有脱敏提示。
- **右侧实时流水线面板**（桌面端）：每条消息进来时，实时显示脱敏结果、六类情绪概率分布、风险等级与命中信号、生成方式与引用来源。**演示时直接讲这一块最有说服力。**
- **情绪档案页**：30 天曲线（按情绪着色的数据点）、本周高频话题、"周报全文"。
- **暖光页**：历史提醒记录 + 24 小时求助渠道。
- **补给页**：按你最近的情绪状态自动生成"心情处方"——出去走走 / 吃点好的 / 做件小事，外加三个内置小游戏（呼吸练习、捏泡泡、涂鸦撕掉）。依据是行为激活（Behavioral Activation）：低落时先安排小而具体的活动，情绪跟着行动走。**这是"预警之后呢"的答案**：系统不只告诉你状态不好，还给你一条今天就能走的路。
- **我的页**：匿名身份 ID、引擎状态、校园求助指数、一键清空。

演示建议动线：发一句"这周连着三天没睡好，一想到实验就烦" → 看右侧面板 → 切到情绪档案看曲线 → 再发"组会又被批评了，感觉自己很没用"触发暖光弹层 → 最后发一句高危表达，展示危机协议。

## 项目结构

```
xinyu/
├── app.py                  # HTTP 服务 + 路由（标准库，零依赖），SSE 流式

├── knowledge.py            # 知识卡语料 + 检索 + 兜底话术 + 边界话术
├── moodkit.py              # 心情补给：行为激活处方 + 走走/吃点/小事/小游戏内容池
├── responder.py            # 本地兜底回复生成（AI 不可用时降级），安全过滤
├── mock_llm.py             # 本地 Mock 模型（验证 AI 链路用，非必需）
├── store.py                # SQLite：消息、提醒、纠正反馈、档案统计、聚合指标
├── make_corpus.py          # 校园语料合成（模板 + 同义改写）
├── train.py                # RoBERTa 微调 + 评测（混淆矩阵 / 高危漏判）
├── campus_corpus.jsonl     # 生成的语料（720 条）
├── public/                 # 前端：index.html / style.css / app.js（SSE 流式渲染）
└── data/                   # 运行时生成（xinyu.db + config.json）
```

## AI 是怎么参与的（不是套壳）

配置好模型后，AI 在四个环节真实参与：

| 环节 | AI 做什么 | 兜底是什么 |
|---|---|---|
| **语义理解** | 每条消息由模型输出结构化判断：情绪、效价、强度、风险等级、核心诉求、潜台词、认知模式（附原文证据） | 规则词典引擎并行判断 |
| **对话回复** | 模型结合知识卡（RAG）+ 对话上下文逐字流式生成 | 本地知识卡话术 |
| **每周小结** | 模型基于真实统计数据（次数/均分/话题分布）写信式周报 | 模板周报 |
| **风险分级** | 模型判断与规则判断**取并集**：任一方报高风险即按高风险处理 | — |

**不可逾越的安全底线**（不依赖模型自觉）：
- L3 高危一律走硬编码危机协议，模型无权覆盖；
- 模型输出流式传输中实时检测诊断/用药类表述，命中立即中断并替换为安全话术；
- 情绪方向冲突时（AI 说正向、规则说负向），取强度更高的一侧——宁可过重不可漏判。

界面上这一切都看得见：AI 回复气泡内嵌"我理解到你想要的是…"洞察条；右下角流水线面板展示双引擎对照（规则 vs AI）；每条回复带"依据 N 条"可查知识卡。

## 配置 AI 模型（30 秒）

**方式一：界面配置（推荐）** —— 打开页面 → 右上角"AI 未连接"徽标 → 选服务商 → 粘贴 API Key → 保存并启用。

内置预设（都是 OpenAI 兼容协议，开箱即用）：

| 服务商 | 默认模型 | 说明 |
|---|---|---|
| DeepSeek | deepseek-chat | 中文强、价格低 |
| 智谱 GLM | glm-4-flash | **免费额度充足，课程项目首选** |
| 通义千问 | qwen3.8-omni-flash | 百炼平台，免费额度**按模型单独开通**（实测 qwen-plus 常报未开通） |
| Moonshot | moonshot-v1-8k | 长文本 |
| SiliconFlow | Qwen2.5-7B-Instruct | 聚合开源模型 |
| 本地 Ollama | qwen2.5:7b | 完全离线，需 `ollama pull` |
| 自定义 | — | 任意 OpenAI 兼容端点 |

**方式二：环境变量**

```powershell
$env:XINYU_LLM_API_KEY="sk-xxx"
$env:XINYU_LLM_BASE_URL="https://api.deepseek.com/v1"
$env:XINYU_LLM_MODEL="deepseek-chat"
python app.py
```

Key 保存在本机 `data/config.json`，界面上永远打码显示，不上传任何地方。

**没有 Key？** 可以跑 `python mock_llm.py` 启动本地 Mock 模型（选"自定义"，地址 `http://127.0.0.1:8900/v1`，模型名 `mock`，Key 随便填）——它用于验证 AI 链路是否打通，不是真模型。

### 报错了怎么读

错误信息里能区分四种完全不同的情况，处理方式也不一样：

| 提示 | 真实含义 | 怎么办 |
|---|---|---|
| 触发免费额度限流（可重试） | Key 有效、模型有权限，只是 RPM/请求次数打满 | 等 10～60 秒再试；别连续狂点，会一直续上 |
| 该模型未开通（不是 Key 错了） | Key 有效，但名下没开这个模型 | 点「**探测可用模型**」自动找出能用的那个 |
| API Key 无效或未授权 | Key 填错 / 过期 | 重新复制，注意别带空格 |
| 余额 / 额度已用尽 | 免费额度真的耗完了 | 换服务商或充值 |

「探测可用模型」会依次真实调用该服务商的候选模型，每行标出**可用 / 未开通 / 被限流**，找到能用的自动填回模型名。实测某通义 Key 的结果就是：`qwen-turbo` 被限流、`qwen-plus`/`qwen-max`/`qwen-long` 全未开通、只有 `qwen3.8-omni-flash` 能用——这种差异光看 HTTP 状态码是分不出来的。

> AI 调用失败**不会让项目坏掉**：自动降级到本地规则引擎，回复照常生成，气泡里会标注降级原因。

## 模型训练与评测

```bash
pip install -r requirements-ml.txt
python make_corpus.py --per 120          # 生成校园语料
python train.py --model hfl/chinese-roberta-wwm-ext --epochs 3
python train.py --rules-baseline         # 不要 torch 也能跑基线对照
```

**当前规则引擎基线（校园测试集 137 条，按说话人切分）**

```
准确率 70.80%
高危类（低落 / 焦虑）漏判  0 条
```

这个数字不漂亮，但它是诚实的、可复现的，而且**高危类一条没漏**——这正是第 11 页验收标准里说的"这个指标比总准确率更要命"。训练脚本会把混淆矩阵和 `eval_report.json` 一起存到 `runs/`，结题时可复查。

> 语料说明：`campus_corpus.jsonl` 目前是**模板合成语料**，用于跑通管线与验证指标口径。正式阶段应替换为访谈/问卷收集的真实表达 —— 脚本已按 `speaker` 字段做切分，防止同一人的表达跨训练/测试集"背答案"。

## 隐私设计（第 8 页"隐私默认匿名"）

- 用户标识是**本机随机 UUID**，不含姓名、学号、任何真实信息；"我的"页可一键更换身份或清空记录。
- 消息正文落库前已完成脱敏。
- **没有**"上报"接口，也没有管理员查询个体数据的接口。
- 校园求助指数只在样本 ≥20 条时输出，且不含任何可定位到个人的字段 —— 数据太少时宁可不出。
